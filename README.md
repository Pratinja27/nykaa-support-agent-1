# Nykaa Support Agent

**Track:** E-commerce & Retail — Nykaa

A retrieval-augmented, tool-using support agent for Nykaa customer support — policy questions such as *"What's the return window on beauty products?"* and order lookups such as *"Where is NYK-1012?"*.

Built on a LangGraph agent, ChromaDB retrieval with two chunking strategies, FastAPI, an MCP tool server, SQLite checkpointing, and timeout/retry resilience.

Runs entirely on `MOCK_LLM` — no API key, no paid account, and no external LLM calls anywhere in the project.

## RAG

Two chunking strategies are used with two separate ChromaDB collections. Both are embedded using the local `all-MiniLM-L6-v2` model.

### Fixed-Size + Overlap

Collection: `nykaa_fixed`

* Chunk size: 220 characters
* Overlap: 40 characters

### Sentence-Based

Collection: `nykaa_sentence`

* One sentence per chunk

### Retrieval Threshold

The similarity threshold was calibrated empirically rather than assumed.

**In-scope similarities:**

* `0.49`
* `0.76`
* `0.70`

**Out-of-scope similarities:**

* `0.13`
* `0.25`

**Runtime threshold:** `0.35`

Below this threshold, the agent answers:

> I don't know.

### Chunking Strategy Comparison

Both strategies were compared on the same 5 queries using Precision@3 and Recall@3.

| Strategy             | Precision@3 | Recall@3 |
| -------------------- | ----------: | -------: |
| Fixed-size + overlap |       0.333 |    1.000 |
| Sentence-based       |       0.333 |    1.000 |

Both scored P@3 = `0.333` and R@3 = `1.000`, but sentence chunking pulled fewer off-topic parent documents, so it is the strategy used at runtime.

## Order Tool & Escalation

The system uses a real 0–1 escalation score rather than a simple boolean.

### Escalation Formula

```text
escalation_score =
    0.60 * delayed_flag
    + 0.40 * (days_since_created / 30)
```

The score is clamped to the `0–1` range.

### Escalation Threshold

**`0.63`**

The threshold was set using the 80th percentile of `days_since_created` on this dataset.

Orders above the threshold are marked for escalation.

## LangGraph Agent

The support agent is implemented using LangGraph.

### Graph Flow

```text
guard
  ↓
classify
  ↓
 ┌───────────────┐
 │               │
RAG            Order
 │               │
 └───────┬───────┘
         ↓
      format
```

The graph contains 5 nodes:

1. `guard`
2. `classify`
3. `rag`
4. `order`
5. `format`

A conditional edge routes policy questions to RAG and order questions to the order tool.

### Memory

JSON-persisted memory is maintained per session.

The implementation demonstrates:

* Remembering an order ID across turns
* Using the remembered order ID in a follow-up question
* Starting a fresh session with no carryover

### Structured Output

Every response is validated against a JSON Schema before being returned.

### Guardrails

The system implements three guardrails:

#### 1. PII Masking

Phone numbers and card last-4 digits are masked before reaching the model or the log.

#### 2. Prompt-Injection Detection

Suspicious prompt-injection attempts are detected before processing.

#### 3. Output Groundedness Check

The generated response is checked for groundedness and refuses to provide ungrounded answers.

All three guardrails have deliberate firing demonstrations.

## Resilience

The system includes checkpointing, timeouts, and retries.

### Checkpointing

Uses:

`langgraph-checkpoint-sqlite`

Database:

`checkpoints.sqlite`

The demonstration:

1. Runs 2 nodes
2. Is interrupted
3. Resumes on the same thread
4. Completes

An execution log proves that completed nodes were not re-run.

### Timeouts

* Per-node timeout: `1.0s`
* Global timeout: `2.0s`

Both are demonstrated firing cleanly against simulated slow calls.

### Retries

Exponential backoff configuration:

| Setting          | Value |
| ---------------- | ----: |
| Maximum attempts |     3 |
| Initial interval |  0.2s |
| Maximum interval |  2.0s |
| Jitter           |  0.1s |

A simulated failure recovers on attempt 3.
